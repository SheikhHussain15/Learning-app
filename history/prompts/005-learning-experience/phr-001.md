## Prompt

# Phase 5 — Specify Prompt
## AI Learning Platform

Use the project **Constitution**, **PRD**, and the approved specifications from **Phases 1–4** as the highest authority.

Generate a complete software specification for **Phase 5 — Learning Experience** only.

Do **NOT** generate implementation code, UI code, folder structures, database migrations, or task lists. This phase defines the complete user learning experience built on top of the existing AI infrastructure and agents.

---

# Objective

Design the end-to-end learning experience that enables users to study processed documents through an interactive workspace, personalized dashboard, AI Tutor, quizzes, flashcards, diagrams, and progress tracking.

This phase focuses exclusively on the user experience layer while consuming outputs produced by Phase 4 AI Agents.

---

# Scope

This specification MUST include only the following deliverables.

---

# 1. Learning Workspace

Specify the complete Learning Workspace for a processed document.

Include:

- Document overview
- Chapter navigation
- Topic navigation
- Summary section
- Explanation section
- Translation section
- Diagram section
- Quiz section
- Flashcards
- Revision Notes
- AI Tutor
- Document metadata

For every optional section define four UI states:

- Not Requested
- Processing
- Failed
- Completed

Users must clearly understand the status of every AI-generated resource.

---

# 2. Dashboard

Specify the learning dashboard.

Include:

- Recent learning
- Learning statistics
- Study progress
- Learning streak
- Personalized recommendations
- Saved notes
- Recently viewed documents
- Quick actions

Specify how every widget obtains its data.

Dashboard data must come from Progress Agent records rather than being calculated in the frontend.

---

# 3. Quiz Experience

Specify the complete quiz-taking workflow.

Include:

- Quiz selection
- Question navigation
- Answer submission
- Instant feedback
- Final score
- Review mode
- Retry workflow

Specify QuizAttempt recording.

Each completed quiz must update Progress Agent events.

---

# 4. Flashcard Review

Specify flashcard learning.

Include:

- Card navigation
- Flip interaction
- Difficulty rating
- Review history
- Basic spaced repetition scheduling
- Progress tracking

Do not implement advanced spaced repetition algorithms.

---

# 5. Diagram Experience

Specify diagram rendering.

Support:

- Mermaid diagrams
- Flowcharts
- Mind Maps
- Timelines
- Concept Maps

Diagrams must render directly from structured data generated by the Diagram Agent.

Users should be able to zoom, pan, and inspect diagrams.

---

# 6. AI Tutor

Specify the AI Tutor.

The Tutor must:

- Answer only from the user's own uploaded documents
- Use LlamaIndex retrieval
- Retrieve relevant ChromaDB chunks
- Cite source references
- Refuse unsupported questions
- Preserve conversation history per document

Specify:

- conversation lifecycle
- retrieval workflow
- grounding requirements
- citation behavior
- follow-up questions
- error handling

The AI Tutor must never hallucinate beyond retrieved document context.

---

# 7. Progress Integration

Specify how every learning interaction records progress.

Include:

- Quiz completion
- Flashcard reviews
- Chapter completion
- Reading progress
- AI Tutor usage
- Diagram interaction
- Revision completion

Specify event recording behavior.

---

# 8. Recommendation Integration

Specify how recommendations appear inside:

- Dashboard
- Learning Workspace

Recommendations must originate from Recommendation Agent outputs.

Define behavior for:

- New users
- Active learners
- Inactive learners

---

# 9. Navigation Experience

Specify application navigation.

Include:

- Dashboard
- Library
- Learning Workspace
- AI Tutor
- Profile

Define responsive navigation behavior.

---

# 10. Design System

Specify the complete design system.

Include:

- Typography scale
- Color palette
- Spacing scale
- Border radius
- Icons
- Buttons
- Cards
- Forms
- Tables
- Dialogs
- Navigation
- Responsive breakpoints

Support:

- Dark Mode
- Light Mode

All UI must remain visually consistent.

---

# 11. Loading States

Specify loading behavior for every screen.

Include:

- Skeleton loaders
- Progress indicators
- Streaming responses
- Lazy loading
- Background refresh

No screen may appear blank while loading.

---

# 12. Empty States

Specify empty states for:

- Dashboard
- Library
- Workspace
- Quiz
- Flashcards
- AI Tutor
- Notes
- Recommendations

Every empty state should guide the user toward the next meaningful action.

---

# 13. Error Handling

Specify handling for:

- Missing AI outputs
- Retrieval failures
- Quiz submission failures
- Tutor failures
- Diagram rendering failures
- Network interruptions

Define user-facing behavior.

---

# 14. Accessibility

Specify accessibility requirements.

Include:

- WCAG AA compliance
- Keyboard navigation
- Screen reader support
- Focus management
- Color contrast
- Responsive layouts

---

# 15. Performance

Specify performance expectations.

Include:

- Dashboard loading
- Workspace loading
- Tutor response time
- Diagram rendering
- Quiz navigation
- Flashcard transitions

---

# Non-Goals

The following MUST NOT appear in this specification.

- Authentication
- File Upload
- Storage
- AI Agent implementation
- Orchestrator implementation
- LlamaIndex implementation
- ChromaDB implementation
- Deployment
- CI/CD
- Infrastructure configuration

Only specify the learning experience.

---

# Risks

Identify UX and architectural risks.

Include:

- AI Tutor hallucination
- Retrieval latency
- Large diagrams
- Long quizzes
- Progress synchronization
- Recommendation accuracy
- Mobile responsiveness

For each risk provide:

- Description
- Impact
- Mitigation

---

# Acceptance Criteria

Translate every PRD acceptance criterion into measurable specifications.

Verify that:

- Users can complete an entire learning journey within the application.
- Dashboard accurately reflects Progress Agent data.
- Quiz attempts generate Progress events.
- Flashcards support review workflows.
- Diagrams render correctly from structured outputs.
- AI Tutor answers are grounded with valid source references.
- Every screen defines loading, empty, processing, and error states.
- No user interface displays blank or broken content during asynchronous operations.
